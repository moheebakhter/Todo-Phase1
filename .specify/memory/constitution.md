# Hackathon 2 – Phase I Todo In-Memory Python Console Application Constitution

## Core Principles

### I. Spec-Driven Development Only
Every feature, bug fix, or refactor must originate from a specification. No "vibe coding" or manual, undocumented changes are permitted. This ensures clarity, alignment, and a traceable history of decisions.

### II. Human-in-the-Loop Agentic Workflow
All code must be generated by the LLM agent based on explicit instructions from the human operator. The operator's role is to provide specifications, review outputs, and guide the agent, not to write code manually.

### III. Clean Code
The codebase must be simple, readable, and maintainable. 
- Follow standard clean code principles.
- Use meaningful, descriptive names for variables and functions.
- Employ functions to ensure a clear separation of concerns.

### IV. Beginner-Friendly CLI
The console application interface must be intuitive and easy to use for beginners. Interactions should be straightforward, with clear prompts and feedback.

### V. Ephemeral Storage
The application must use in-memory storage only. No persistent storage solutions like databases or file I/O are to be implemented. State is lost when the application exits.

### VI. Minimalism
Avoid unnecessary complexity. Do not introduce external frameworks or libraries unless absolutely essential and justified by a specification.

## Functional Requirements
- **Add Task**: Ability to add a new todo task with a title and an optional description.
- **View Tasks**: Display all tasks, showing their title, description, and status (e.g., Pending, Completed).
- **Update Task**: Modify the title or description of an existing task.
- **Delete Task**: Remove a task from the list.
- **Complete Task**: Mark a task as completed.

## Technical Standards & Constraints
- **Language**: Python 3.13+
- **Platform**: Console-based application (CLI).
- **Architecture**: No GUI or web frameworks.
- **Source Code**: All source code must reside in a `/src` directory.
- **Documentation**: A `README.md` with usage instructions is required.
- **Process History**: All specifications and prompt history must be captured in the `specs/` and `history/` directories, respectively.

## Governance
This Constitution is the authoritative source of truth for project standards and workflow. All development activities, reviews, and artifacts must comply with its principles. Amendments require documented justification and review.
